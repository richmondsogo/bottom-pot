This document maps all **nine** monitored ATS company-board adapters under [`src/providers/`](../../src/providers/board_adapters.py) and their orchestration in [`src/monitoring/board_monitor.py`](../../src/monitoring/board_monitor.py) across the nine contract concerns required by Step 57 Phase 4a.

Shared contract, fingerprinting, SSRF/HTTP resilience, pagination, detail hydration, and deterministic clock primitives are enforced across all 9 providers by the 156-test offline conformance suite in [`tests/conformance/test_provider_conformance.py`](../../tests/conformance/test_provider_conformance.py).

## Justified Per-Provider Differences & Module Line Counts

1. **Recruitee 16 MiB default cap (`settings.recruitee_board_max_response_bytes`)**: Real Recruitee boards return the full tenant payload with inline HTML descriptions in one JSON request (for example, the checked-in `tether` fixture is ~5.97 MiB). Using a 16 MiB default avoids false truncation on legitimate boards while still enforcing explicit `max_response_bytes` overrides and streaming byte limits.
2. **SmartRecruiters omits page-0 `If-None-Match` short-circuiting**: SmartRecruiters paginates sequentially across multiple offset URLs (`offset=0, 100, ...`); caching an ETag only on page 0 would miss edits on later pages. Instead, SmartRecruiters fetches the full atomic snapshot, computes the canonical board fingerprint, and short-circuits (`not_modified=True`) when the fingerprint is unchanged and no detail retries/hydrations are due.
3. **One vs two missing-confirmation strikes (`ReconciliationPolicy`)**: Single-request atomic JSON APIs (Greenhouse, Lever, Ashby, Workable, Recruitee) use `missing_confirmation_threshold=1`; paginated, bilingual dual-feed, RSS/HTML fallback, or higher-flake boards (SmartRecruiters, Teamtailor, Personio, Pinpoint) require `missing_confirmation_threshold=2` consecutive complete snapshots before closing a missing job.
4. **Teamtailor partial-RSS fallback mode**: When RSS hits the 100-item ceiling and HTML fallback fails, Teamtailor returns `success=True, snapshot_complete=False, incomplete_reason=...` to keep the 100 RSS postings fresh without triggering missing-job closures (`ReconciliationPolicy.reconcile` skips reconciliation whenever `not snapshot_complete`).
5. **Module line counts**: Eight of nine per-provider modules (`greenhouse.py`: 315, `lever.py`: 235, `ashby.py`: 264, `workable.py`: 708, `recruitee.py`: 410, `teamtailor.py`: 707, `personio.py`: 653, `pinpoint.py`: 609) are `<= 800` lines, and `board_adapters.py` was reduced from 4,313 to 112 lines and removed from `GRANDFATHERED_LARGE_MODULES`. `smartrecruiters.py` stands at 865 lines (well below CI's 1,500-line ceiling) because SmartRecruiters uniquely combines multi-page offset pagination with fair priority-queued `ref`-URL detail hydration and cached-listing metadata backfill in one adapter.

## Defects Exposed and Fixed by C1–C12

Running the new 156-test conformance suite against the pre-refactor baseline yielded **95 failed, 61 passed**, surfacing concrete cross-provider bugs that are now fixed and locked down (**156 passed, 0 failed**):

| Clause | Defect Exposed in Baseline | Fix Applied |
|---|---|---|
| C1 | Greenhouse, Ashby, and Workable accepted `{}` (missing `"jobs"` key) as an empty board, risking mass false closure on upstream schema drift. | Strict root-shape validation requiring `isinstance(data, dict)` and `isinstance(data.get("jobs"), list)` (or `isinstance(data, list)` for Lever). |
| C3 | Greenhouse, Lever, Ashby, Workable, and Recruitee did not reject duplicate job IDs inside one snapshot, and no cross-poll ID-drift detector existed. | Fail-closed duplicate-ID rejection across all 9 snapshots plus centralized `detect_id_drift` in `contract.py` & `BoardMonitor`. |
| C4 | Greenhouse (`v37:` + `content[:64]` + `[:16]`), Lever (`v36` + `desc[:200]` + `[:16]`), and Workable (`SHA-1[:12]`) truncated/non-canonical hashes missed deep edits; Ashby/Recruitee varied on whitespace; Personio/Pinpoint called private `_teamtailor_rss_item_hash`. | Unified [`canonical_content_hash`](../../src/providers/fingerprint.py) & [`compute_board_fingerprint`](../../src/providers/fingerprint.py) producing whitespace/key-order-invariant 64-hex SHA-256 across all 9 providers. |
| C5 | Recruitee ignored `ETag` / `Last-Modified` and lacked `304 Not Modified` short-circuiting. | Added `If-None-Match` / `If-Modified-Since` headers and `304` handling to `RecruiteeBoardAdapter`. |
| C6 / C7 | Greenhouse, Lever, and Ashby called raw `client.get().json()` bypassing `resilience_manager` and byte limits; Workable & SmartRecruiters used unbounded buffered `throttled_get`; `BoardMonitor` constructed bare `httpx.AsyncClient`; `CancelledError` could be swallowed in `gather(..., return_exceptions=True)`. | Routed every provider call through [`fetch_provider_bytes`](../../src/providers/http.py) (enforced by AST test `C7`), wired `create_ssrf_safe_async_client` in `BoardMonitor`, and re-raised `asyncio.CancelledError` everywhere. |
| C8 | Missing-confirmation thresholds (`1` vs `2`) were ad-hoc integers on return sites; `FailureKind` did not exist. | Added typed `FailureKind`, `ReconciliationPolicy`, `failure_result`, and `reconcile()` in [`contract.py`](../../src/providers/contract.py). |
| C9 | SmartRecruiters formatted `raw_workplace_type = f"remote={None},hybrid={None}"` in [`src/ats/ats_api_client.py`](../../src/ats/ats_api_client.py), causing `JobExtractionService` substring fallback to misclassify neutral postings as `"hybrid"` (violating ADR 0001). | Set `raw_workplace_type = None` in `smartrecruiters_payload_to_raw` whenever both `remote` and `hybrid` booleans are `None`. |
| C10 | Direct `time.time()` and `datetime.now()` calls inside adapters and `JobExtractionService` prevented deterministic poll output under an injected clock. | Added [`src/core/clock.py`](../../src/core/clock.py) (`use_clock`, `epoch_now`, `utc_now`) and wired all 9 adapters + extraction + canonical adapter + monitor to honor injected clocks. |
